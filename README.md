# Story Crafting

一套面向小说/故事创作的完整流程引擎，作为 Claude Code 的 skill 使用。核心理念：**创作不是一蹴而就的灵光，而是一条"发散-收敛"交替的菱形链**。每个阶段都有明确的产出物，AI 在发散阶段做头脑风暴搭子（多给方向、不评判），在收敛阶段做结构教练（给清单、给公式、直接诊断）。

## 它解决什么问题

新手写小说最常见的三种卡法：

1. **不知道从哪开始** -- 脑子里有画面但写不出，或者想写但不知道写多长
2. **写到一半卡住** -- 开头几章还行，中段垮了，不知道怎么推进
3. **改稿只会逐句润色** -- 结构性问题（人物动机断了、伏笔没填）靠改句子救不回来

这个 skill 把创作拆成六个阶段，每阶段强制落地成模板化产出（人物卡、节拍表、章节大纲、修改 checklist），并支持从任意阶段切入。修改阶段会先做诊断分流，结构问题主动带你退回前面阶段重新发散，而不是在原地死磕句子。

## 核心特性

- **入口问诊用大白话**：不问"你想用三幕式还是英雄之旅"，而是问"这个故事大概几句话能讲完？""你更希望读者记住一个人，还是记住一件事？" -- AI 自己映射到对应框架
- **按篇幅分叉**：短篇/中篇/长篇各有 SOP，差异不是字数，是"要不要维护跨章节状态"
- **表演型短篇适配**：单口喜剧、演讲、独白这类非叙事短篇，节拍表有专门映射
- **修改阶段做诊断分流**：先判断是句子问题还是结构问题，结构问题退回对应阶段
- **知识库联动**：默认从本地小说写作知识库提取方法论，路径可配置
- **与其他 skill 联动**：包装发布阶段可调用 `/dbs-hook`、`/dbs-xhs-title`、`/xiaotao-writer` 等（非强制依赖）

## 六个阶段

| 阶段 | 核心产出 | AI 角色 |
|---|---|---|
| 1. 创意与人物 | 一句话故事 + 人物卡 | 发散：给 3-5 个方向不评判；收敛：落地四格人物卡 |
| 2. 结构大纲 | 节拍表/章纲/卷纲 | 收敛：套用三幕式、英雄之旅等现成框架 |
| 3. 场景/章节写作 | 逐章草稿 | 混合：每场戏给 2-3 版台词/意象，收敛成目标-冲突-结果 |
| 4. 修改润色 | 定稿 + 修改记录 | 收敛 + 退回：先诊断句子还是结构问题，结构问题退回前面阶段 |
| 5. 包装发布 | 标题 + 简介 + 发布建议 | 收敛：套用高转化公式 |
| 6.（入口问诊） | 篇幅类型 + 驱动类型 + 切入阶段 | 用 3 个生活化问题定方向 |

## 篇幅差异

| 维度 | 短篇 | 中篇 | 长篇/连载 |
|---|---|---|---|
| 核心特征 | 单一转折点 | 主线 + 1-2 支线 | 菱形链嵌套 |
| 人物 | 单人物单欲望 | 主角 + 1-2 重要配角 | 人物小传库 |
| 大纲 | 节拍表 5-7 拍 | 章节级大纲 | 卷纲 + 章纲 + 世界观圣经 |
| 状态维护 | 不需要 | 关系网 | 伏笔表 + 关系表 + 世界观表 + 时间线 |
| 修改重点 | 句子润色 | + 支线闭合 | + 伏笔回收 + 人设一致性 + 世界观一致性 |

## 使用示例

**从入口问诊开始（纯新手）：**
> "我想写一个关于急诊科医生的故事，但不知道从哪开始，也不知道该写多长。"

**直接切入人物阶段：**
> "我想做《红楼梦》女性角色的单口喜剧，每个人物 5-8 分钟。我已经有人物选型了（林黛玉、王熙凤、薛宝钗），但不知道怎么给每个人物设计弧光。"

**直接切入大纲阶段：**
> "我在写一个 15 分钟的短片，叫《没有如果》。主角获得能看到'如果当时选了另一条路'的能力，但每次看都会失去一段真实记忆。帮我把节拍搭出来。"

## 测试结果

第一轮 iteration（3 个测试用例，with-skill vs without-skill 对照）：

| Eval | with-skill | without-skill |
|---|---|---|
| 入口问诊 | 8/8 (100%) | 1/8 (12%) |
| 人物直接切入 | 6/6 (100%) | 5/6 (83%) |
| 大纲直接切入 | 7/7 (100%) | 3/7 (43%) |
| **整体** | **21/21 (100%)** | **9/21 (46%)** |

skill 在三个测试用例上全部通过断言，baseline 只通过 46%。主要差异在结构化产出（intake 文件、四格人物卡、节拍表表格）和流程规范（5-7 拍、四格必填、不乱走入口问诊）。

## 设计理念

### 菱形链：发散-收敛交替

每个阶段不是单纯地"想"或"做"，而是先炸开再收拢 -- 前一个收拢点，天然就是下一个炸开的起点。

- **发散阶段**：AI 像头脑风暴搭子，多给方向、不评判优劣，用"如果……会怎样"刺激联想
- **收敛阶段**：AI 像结构教练，给清单、给公式、直接诊断哪里断了

### 修改阶段要"往回跳"

新手在修改时最常见的死结：只会逐句润色（收敛动作），但结构性问题（人物动机断了、中段垮了）的解法需要退回"人物"或"情节"阶段重新发散一轮，而不是在原地死磕句子。skill 在修改阶段显式做一步诊断分流：先判断"这是句子问题还是结构问题"，结构问题主动把人带回对应的发散引擎。

### 长篇 = 菱形链嵌套

短篇基本就是四个菱形走一遍；长篇/连载则是"大菱形套小菱形" -- 每一卷、每一条人物弧光都要重新走一次内核提炼 -> 人物 -> 情节的迷你循环，外层还要有一条总纲级菱形链把这些子循环串起来。这比单纯说"长篇大纲颗粒度更细"更准确。
